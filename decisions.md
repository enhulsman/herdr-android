# Decisions: herdr Android client

One line per decision, newest last. Date, decision, why.

- 2026-10-31: Design first (1-2 sessions), then a milestone-gated background build (M1-M4), each ending in a phone check by Ezra.
- 2026-10-31: The phone stays a viewer/steerer: no agents and no npm on it.
- 2026-10-31: Ask the herdr maintainers (GitHub discussion on herdrdev/herdr-app) before writing code. (Superseded below: no post.)
- 2026-10-31: Alerts with the app closed go through UnifiedPush via the self-hosted ntfy (no Google FCM). Pattern follows MollySocket.
- 2026-10-31: The push watcher runs on each herdr-core machine (local connection, outbound to ntfy only), not on the VPS: a VPS watcher would need SSH into the workstation, and herdr-core access is an unrestricted shell.
- 2026-10-31: The push payload is encrypted with UnifiedPush web-push encryption (RFC 8291) and carries machine, agent and kind only; ntfy sees ciphertext. Chosen over an empty Molly-style wake-up so alerts show instantly and work without the phone reaching the machine.
- 2026-10-31: Release APKs are signed in GitHub Actions; the key sits in a protected environment whose signing step waits for Ezra's approval (from the phone). Key backup in Bitwarden. Why: a signing-key holder can ship an update that steals the app's SSH key, which is shell on the machines.
- 2026-10-31: Stack: Kotlin + Jetpack Compose UI over a Rust core that uses libghostty-vt (same terminal engine as the Mac app). The 2-hour test built libghostty-vt for Android arm64 cleanly. Fallback if it misbehaves on a device: Termux's terminal-emulator/terminal-view libraries (Apache 2.0).
- 2026-10-31: Themes: the Mac's six (graphite, ink, moss, paper, atom-one-dark, win98) copied as data; phone-local setting, follows system light/dark with defaults graphite/paper. No custom theme files in v1.
- 2026-10-31: Changes panel on the phone, view-only (no commit/stage/discard). Files panel after M4.
- 2026-10-31: Alerts use two Android notification channels, "Needs you" (loud, lock screen) and "Finished" (quiet, can be off); sound/vibration/DND via Android settings; per-machine mute in the app.
- 2026-10-31: The phone cannot SSH into the Mac (confirmed by Ezra). v1 connects to WSL only; the design stays multi-machine for other OpenSSH hosts. Mac alerts-only via an outbound watcher is a parked idea.
- 2026-10-31: Milestone order: M1 connect + agent list; M2 live terminal + keyboard together (keys row, compose key, phone size while typing); M3 alerts; M4 spaces drawer, wide layout, themes; M5 Changes. No chat-style composer: input is the native terminal plus keyboard.
- 2026-10-31: Typing on the phone resizes the terminal to the phone by default (no dialog); the desk takes its size back on its next input, as herdr itself does. Watching alone stays observe-only.
- 2026-10-31: A compose key in the keys row opens a text field (autocorrect, swipe, dictation) whose text is pasted into the terminal without Enter (bracketed paste), as Termux does.
- 2026-10-31: Phone key protection: try C first (Keystore key requires fingerprint/device credential, valid 30 min; one prompt on opening the app or tapping an alert). If the UX is poor at the M1 phone check, fall back to B (app lock after 15 min in the background, key itself unbound). Alerts never need the key.
- 2026-10-31: v1 = M1-M3 (connect + list, live terminal + keyboard, alerts) with themes graphite/paper following system; v1.1 = M4 (spaces, tiles, peek, wide layout, other four themes) and M5 (Changes). Mainly sets where the background build stops.
- 2026-10-31: Maintainer post (one GitHub discussion, drafted in Ezra's voice, shown verbatim before posting, posted by Ezra) would have asked five things: third-party Android client welcome / own mobile plans; client-owned flat doc names (`hdroid-push`) as a stable contract; viewer presence or last-input time on Terminal; push support in core; upstreaming the shared protocol code as a client crate. No Mac, client or setup details. (Superseded below: no post.)
- 2026-10-31: No maintainer post. Maintainers rarely answer in herdrdev/herdr Discussions (1 maintainer reply in the 100 most recently active threads), and the same question about stable contracts for third-party mobile clients (#3913, #4852) went unanswered. Nothing in the spec waits on upstream; we rely on the client-owned doc name `hdroid-push` and the grace delay without confirmation. Existing clients checked first: Whip (native Android/iOS, Play Store) speaks classic herdr protocol 17-22, not herdr-core, and pushes through its relay + Expo + FCM; Kelpie is iOS-only; Shepherdr, Bordr, herdr web ui, Pairfob, Mobaide are web/PWA. herdr-core support and Google-free push remain the reason to build.
- 2026-11-01: Visual design signed off (task 0.2): the herdr-app design system as is (graphite/paper colours from `resolve()`, Geist + JetBrains Mono, the Mac sidebar's status language), arranged for the phone, with the needs-you cards and queue strip as the signature. Renders in `design/`, values in `design-tokens.json`, explanation in `design-brief.md`.
- 2026-11-01: Contrast: keep the Mac values for now although dim text (2.6-3.5:1) and the paper status headers (4.1-4.45:1) are under WCAG AA 4.5:1. Follow-up: judge outdoors at the M1 phone check; the AA-passing replacements are in `design-tokens.json` under `accessibility.followUp`.
- 2026-11-01: Repositories: code private in `herdr-android`; signing and signed releases in a separate public `herdr-android-releases`. Reason: on Ezra's plan a required reviewer on an environment works only in public repositories, and private-with-auto-signing would let anything on WSL that can tag (the `gh` login can, without the phone prompt) put a signed update on the phone. Obtainium follows the public repo (no token). When the code goes public, signing moves there with the same key and the releases repo is archived. (Superseded below: one private repo.)
- 2026-11-01: Repository stays public-ready: no homelab hostnames, IPs, ports, private domains, home paths or real project names in tracked files or history. Real values in untracked `local/setup.md`; a local pre-commit hook checks a local denylist. History was scrubbed with git filter-repo before the first push.
- 2026-11-01: Superseded the two-repo plan the same day: one private repo, releases sign automatically on a `v*` tag. The control is Ezra's manual install: Obtainium (read-only token) never installs in the background, and before installing he checks that the tag is his and on `main`. The signing key is a secret of the `release` environment limited to `v*` tags, so a workflow on another branch cannot read it. The empty public `herdr-android-releases` repo is no longer needed.
- 2026-11-01: Release signing moved to a separate `workflow_run` workflow (`release-sign.yml`) that always runs main's version of the file. Reason (Codex adversarial review, high): a tag-triggered workflow runs the workflow file from the tag itself, so a modified off-main `v*` tag could rewrite its own gate. The gate now checks through the API that the tag points at the built commit, that commit is on main, VERSION matches and the versionCode is above every published release; the `release` environment's deployment policy is therefore "branch main" instead of "tags v*". Supersedes the "limited to v* tags" detail above.
- 2026-11-01: Terminal engine confirmed: libghostty-vt stays, no Termux fallback. Spike A (M0.5) on the Pixel 10 Pro XL, Android 17, `spike` build type (optimized, not debuggable): an invented agent session at 200x60, 4 KiB per display frame, nearly every row redrawn each frame because the output scrolls (187 KiB of frame data per frame). Over 840 frames: engine and encoding p95 3.1 ms, drawing rows p95 8.3 ms, total work p95 11.3 ms (max 15.9), frame interval p95 16.7 ms, 1 frame over 16.7 ms; the on-device grid check passed. The engine is linked statically (the shared library's soname `libghostty-vt.so.0` does not package on Android). Drawing is the larger cost; at 120 Hz (8.3 ms) it would need a glyph cache or scrolling the bitmap instead of redrawing it, which M1 can pick up.
