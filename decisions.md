# Decisions: herdr Android client

One line per decision, newest last. Date, decision, why.

- 2026-10-31: Design first (1-2 sessions), then a milestone-gated background build (M1-M4), each ending in a phone check by Ezra.
- 2026-10-31: The phone stays a viewer/steerer: no agents and no npm on it.
- 2026-10-31: Ask the herdr maintainers (GitHub discussion on herdrdev/herdr-app) before writing code. (Superseded below: no post.)
- 2026-10-31: Alerts with the app closed go through UnifiedPush via the self-hosted ntfy (no Google FCM). Pattern follows MollySocket.
- 2026-10-31: The push watcher runs on each herdr-core machine (local connection, outbound to ntfy only), not on the VPS: a VPS watcher would need SSH into the workstation, and herdr-core access is an unrestricted shell.
- 2026-10-31: The push payload is encrypted with UnifiedPush web-push encryption (RFC 8291) and carries machine, agent and kind only; ntfy sees ciphertext. Chosen over an empty Molly-style wake-up so alerts show instantly and work without the phone reaching the machine.
- 2026-10-31: Release APKs are signed in GitHub Actions; the key sits in a protected environment whose signing step waits for Ezra's approval (from the phone). Key backup in Bitwarden. Why: a signing-key holder can ship an update that steals the app's SSH key, which is shell on the machines.
- 2026-10-31: Stack: Kotlin + Jetpack Compose UI over a Rust core that uses libghostty-vt (same terminal engine as the Mac app). The 2-hour test built libghostty-vt for Android arm64 cleanly. Fallback if it misbehaves on a device: Termux's terminal-emulator/terminal-view libraries (Apache 2.0).
- 2026-10-31: Themes: the Mac's six (graphite, ink, moss, paper, atom-one-dark, win98) copied as data; phone-local setting, follows system light/dark with defaults graphite/paper. No custom theme files in v1.
- 2026-10-31: Changes panel on the phone, view-only (no commit/stage/discard). Files panel after M4.
- 2026-10-31: Alerts use two Android notification channels, "Needs you" (loud, lock screen) and "Finished" (quiet, can be off); sound/vibration/DND via Android settings; per-machine mute in the app.
- 2026-10-31: The phone cannot SSH into the Mac (confirmed by Ezra). v1 connects to WSL only; the design stays multi-machine for other OpenSSH hosts. Mac alerts-only via an outbound watcher is a parked idea.
- 2026-10-31: Milestone order: M1 connect + agent list; M2 live terminal + keyboard together (keys row, compose key, phone size while typing); M3 alerts; M4 spaces drawer, wide layout, themes; M5 Changes. No chat-style composer: input is the native terminal plus keyboard.
- 2026-10-31: Typing on the phone resizes the terminal to the phone by default (no dialog); the desk takes its size back on its next input, as herdr itself does. Watching alone stays observe-only.
- 2026-10-31: A compose key in the keys row opens a text field (autocorrect, swipe, dictation) whose text is pasted into the terminal without Enter (bracketed paste), as Termux does.
- 2026-10-31: Phone key protection: try C first (Keystore key requires fingerprint/device credential, valid 30 min; one prompt on opening the app or tapping an alert). If the UX is poor at the M1 phone check, fall back to B (app lock after 15 min in the background, key itself unbound). Alerts never need the key.
- 2026-10-31: v1 = M1-M3 (connect + list, live terminal + keyboard, alerts) with themes graphite/paper following system; v1.1 = M4 (spaces, tiles, peek, wide layout, other four themes) and M5 (Changes). Mainly sets where the background build stops.
- 2026-10-31: Maintainer post (one GitHub discussion, drafted in Ezra's voice, shown verbatim before posting, posted by Ezra) would have asked five things: third-party Android client welcome / own mobile plans; client-owned flat doc names (`hdroid-push`) as a stable contract; viewer presence or last-input time on Terminal; push support in core; upstreaming the shared protocol code as a client crate. No Mac, client or setup details. (Superseded below: no post.)
- 2026-10-31: No maintainer post. Maintainers rarely answer in herdrdev/herdr Discussions (1 maintainer reply in the 100 most recently active threads), and the same question about stable contracts for third-party mobile clients (#3913, #4852) went unanswered. Nothing in the spec waits on upstream; we rely on the client-owned doc name `hdroid-push` and the grace delay without confirmation. Existing clients checked first: Whip (native Android/iOS, Play Store) speaks classic herdr protocol 17-22, not herdr-core, and pushes through its relay + Expo + FCM; Kelpie is iOS-only; Shepherdr, Bordr, herdr web ui, Pairfob, Mobaide are web/PWA. herdr-core support and Google-free push remain the reason to build.
- 2026-11-01: Visual design signed off (task 0.2): the herdr-app design system as is (graphite/paper colours from `resolve()`, Geist + JetBrains Mono, the Mac sidebar's status language), arranged for the phone, with the needs-you cards and queue strip as the signature. Renders in `design/`, values in `design-tokens.json`, explanation in `design-brief.md`.
- 2026-11-01: Contrast: keep the Mac values for now although dim text (2.6-3.5:1) and the paper status headers (4.1-4.45:1) are under WCAG AA 4.5:1. Follow-up: judge outdoors at the M1 phone check; the AA-passing replacements are in `design-tokens.json` under `accessibility.followUp`.
- 2026-11-01: Repositories: code private in `herdr-android`; signing and signed releases in a separate public `herdr-android-releases`. Reason: on Ezra's plan a required reviewer on an environment works only in public repositories, and private-with-auto-signing would let anything on WSL that can tag (the `gh` login can, without the phone prompt) put a signed update on the phone. Obtainium follows the public repo (no token). When the code goes public, signing moves there with the same key and the releases repo is archived. (Superseded below: one private repo.)
- 2026-11-01: Repository stays public-ready: no homelab hostnames, IPs, ports, private domains, home paths or real project names in tracked files or history. Real values in untracked `local/setup.md`; a local pre-commit hook checks a local denylist. History was scrubbed with git filter-repo before the first push.
- 2026-11-01: Superseded the two-repo plan the same day: one private repo, releases sign automatically on a `v*` tag. The control is Ezra's manual install: Obtainium (read-only token) never installs in the background, and before installing he checks that the tag is his and on `main`. The signing key is a secret of the `release` environment limited to `v*` tags, so a workflow on another branch cannot read it. The empty public `herdr-android-releases` repo is no longer needed.
- 2026-11-01: Release signing moved to a separate `workflow_run` workflow (`release-sign.yml`) that always runs main's version of the file. Reason (Codex adversarial review, high): a tag-triggered workflow runs the workflow file from the tag itself, so a modified off-main `v*` tag could rewrite its own gate. The gate now checks through the API that the tag points at the built commit, that commit is on main, VERSION matches and the versionCode is above every published release; the `release` environment's deployment policy is therefore "branch main" instead of "tags v*". Supersedes the "limited to v* tags" detail above.
- 2026-11-01: Terminal engine confirmed: libghostty-vt stays, no Termux fallback. Spike A (M0.5) on the Pixel 10 Pro XL, Android 17, `spike` build type (optimized, not debuggable): an invented agent session at 200x60, 4 KiB per display frame, nearly every row redrawn each frame because the output scrolls (187 KiB of frame data per frame). Over 840 frames: engine and encoding p95 3.1 ms, drawing rows p95 8.3 ms, total work p95 11.3 ms (max 15.9), frame interval p95 16.7 ms, 1 frame over 16.7 ms; the on-device grid check passed. The engine is linked statically (the shared library's soname `libghostty-vt.so.0` does not package on Android). Drawing is the larger cost; at 120 Hz (8.3 ms) it would need a glyph cache or scrolling the bitmap instead of redrawing it, which M1 can pick up.
- 2026-11-01: Phone key confirmed: ECDSA P-256 in the Android Keystore, non-exportable, in StrongBox (the Pixel has it), user authentication (biometric or device credential) valid 30 minutes; no wrapped Ed25519 fallback. Spike B (M0.6) on the Pixel 10 Pro XL (GrapheneOS): russh signs through a Kotlin callback (`SshSigner`), DER converted to the SSH wire format in Rust; a 30-minute and a 20-second key against a throwaway sshd over `adb reverse`, with a `restrict,command=` line. Signing 48-91 ms, connect plus sign-in about 0.3 s. An expired window surfaces as `NeedsUserAuth`, the app prompts and runs again; one prompt unlocks every auth-bound key for its own window (the 30-minute key did not prompt after the 20-second key's prompt), and per Android a device unlock counts as authentication too, so after unlocking the phone the app often will not prompt at all. Judge that at the M1 phone check against fallback B.
- 2026-11-01: On GrapheneOS the network is a per-app runtime permission (Network). An update that first declares INTERNET arrived with it off on the spike build, and the app failed with EPERM until it was granted. The app gains networking in M1, so the M0.8 update (v0.0.1 to v0.0.2) must check Network is on after the update, and the app should say "Network permission is off" on EPERM, not "connection failed".
- 2026-11-01: Push confirmed, no VAPID. Spike C (M0.7): the spike app registered through the UnifiedPush connector 3.3.5 with the ntfy app as distributor (endpoint on the self-hosted server); `herdr-push` encrypted with `ece` (RFC 8291 aes128gcm) and POSTed with a Bearer token of a dedicated ntfy user `herdr-push` (write-only on `up*`, no read; anonymous writes to the topic are refused). ntfy answered 200 to both test pushes and the connector decrypted them: a 92-byte JSON payload and a 3967-byte payload of every byte value (body 4070 bytes, the most one record and the 4 KiB cap allow), SHA-256 identical on both ends. `ece` pads to 128-byte multiples, which also hides payload length. The `up*` wildcard is needed because the phone mints a new random topic on each registration; Molly's topic is already anonymously writable, so the token adds nothing there and no per-topic deny was set.
- 2026-11-01: M1 scope choices (Ezra): tapping an agent in M1 opens a small read-only sheet (name, machine, state, request) that marks it seen, until the terminal arrives in M2; an agent that finished while the app was closed shows as Done/unseen, using the turn counter the phone remembers per terminal; the spec scenario "unlocked phone in other hands -> no connection" is reworded to "not unlocked or authenticated in the last 30 minutes" (a device unlock opens the key's window, M0.6), and the real trade-off is settled at M1.5 with C vs B. Release order: v0.0.2 is the first M1 build and creates the key; v0.0.3 (M1.5) installs over it and closes M0.8.
- 2026-11-02: Background connections (Ezra, M1.5 item 7): the phone's OS ends them, not the app. About 5 s after herdr leaves the foreground with no visible notification, the system destroys its TCP sockets (logcat: InetDiagMessage "Destroyed live tcp sockets for uids={<app uid>}"), so the app's 60 s grace never runs; on return it reconnects at once, rarely with a key prompt. Accepted for now: the 60 s timer stays as a backstop for phones that do not do this, alerts go through UnifiedPush and never need the connection. Revisit at M2, when a reconnect also reattaches the open terminal: a "stay connected" option would keep the connection with a visible notification. Later, maybe: the same notification as an alert path for people without a UnifiedPush distributor; catch: a reconnect in the background needs the phone key, which only signs within 30 minutes of an unlock, so alerts could silently stop until the next unlock.
- 2026-11-02: GrapheneOS answers the app's own INTERNET permission check with "granted" while its Network toggle is off (seen on the phone: the package manager says granted=false, the app's check said granted), and fails the name lookup instead of refusing the socket. The app tells the cause by asking for a socket after a failed connect (EPERM/EACCES means Network is off).
- 2026-11-02: Dim text (Ezra, M1.5 item 9): the Mac's values stay the default ("Text contrast: Like the Mac"); "Higher" (the AA values from design-tokens.json `accessibility.followUp`) stays as the option for people who need it. Outdoors so far the Mac values read fine.
- 2026-11-02: Fingerprint (Ezra, M1.5 item 8): keep C, the phone key bound to user authentication for 30 minutes; no app lock (B). Unlocking the phone counts as that authentication, so in a day of use no "Unlock the SSH key" prompt appeared; only opening the app after more than 30 minutes of screen-on since the last unlock asks once. Most secure, and no burden. Revisit if that prompt turns out to get in the way.
- 2026-11-02: Terminal padding and keyboard (Ezra, before M2): the grid is drawn inside the Mac pane's padding, 10 dp at the sides and 6 dp at the top, in the terminal background (herdr-app's `terminal_padding` default; Claude Code itself starts at column 0, so the margin is the terminal app's). Phone size while typing is about 53 columns. Hiding the keyboard while typing grows the grid to the full height (one resize once the keyboard settles; Claude Code redraws, which can leave a duplicate of its transcript in scrollback); the keys row stays. Renders 3, 4, 4b and 5 updated. Instant-open cache key: bound to the same 30-minute user authentication as the phone key. No "stay connected" option in M2; a return to the app reconnects and reattaches, the cache covers the gap.
- 2026-11-03: Enter in the keys row (Ezra, M2 phone check item 5): the swipe-up shelf was not found without being told, so enter sits in the main row, after the arrows (down, down, enter under one thumb), and leaves the shelf. Ctrl+c stays in the shelf (ctrl, then c also works). The renders show the row without it; design-tokens.json `components.keysRow.keys` now lists it.
- 2026-11-03: Scrolling and tapping a full-screen program (Ezra, M2 phone check item 4): Claude Code in its fullscreen mode sits on the alternate screen and keeps its own history; herdr sends history for the main screen only, so the phone had nothing to scroll. Copy the desk app: a flick sends the program mouse wheel events (arrow keys on the alternate screen without the mouse), one per row; while watching, the first flick takes over at the phone's size like the first key, since herdr drops input from a watch-only attach. While typing, a tap also clicks the tapped cell for a program that tracks the mouse; while watching it does not (the takeover changes the grid under the finger). The main screen still scrolls locally.
- 2026-11-03: Keys rows and the keyboard (Ezra, M2 phone check): two rows of nine, both always shown while typing, replacing the swipe-up shelf: `esc ctrl alt tab [keyboard] - / ↑ ~` over `^C ⇧⇥ \ ⏎ [compose] | ← ↓ →`. Termux-like, but ctrl+c and enter on the left, away from the arrows (a slip next to an arrow should not send or stop), the keyboard key in the middle. A tap on the terminal never opens the keyboard: while typing it only clicks, while watching it takes over at the phone's size without input (to read and click); the keyboard key shows and hides the keyboard, the watching chip still opens it to type. Shift+tab added for Claude Code's mode switch. The area below a wide desk grid is now terminal background, no dashed line (fit-to-height rejected: Claude Code wraps at the desk's width, so readable text would run off the right edge). Later, not v1: keys the user can arrange, as Termux's extra-keys.
- 2026-11-03: Opening and moving between agents (Ezra, M2 phone check round 2): opening an agent takes over at the phone's size at once (one active attach), since tapping the agent in the list is already the interaction; going back detaches and the desk takes its own size back. No record of who typed last. The desk's own input still takes the size back while the phone is open, and the phone then watches. On the title bar, up and down step through the agents that need you (down retraces the walk), left and right walk every agent in list order like tabs.
- 2026-11-03: No "untested version" notice (Ezra): a newer herdr-core connects with no warning. CI already runs the protocol suite against the latest release (a failure blocks a release); bugs in a newer core become GitHub issues. Too-old cores are still refused. The notice also showed on local debug builds for every core above the pin, as only release builds stamped the tested version.
- 2026-11-03: herdr-push build choices (M3.2), no open questions: the watcher connects to the configured socket itself (`herdr-core connect` would autostart a core) and exits with "no core: socket not set" when the config names none; the config is `key = value` lines (no TOML dependency); each `hdroid-push` entry carries the phone's own name for the machine, echoed as `machine` in pushes; with no `herdr-app` document every agent may alert (a CLI-only user would otherwise never get one), noted as "no layout document"; the first canary goes out at once on a fresh install, so the path is proven before the 6-hour cycle; a test request is one new `test` value per phone entry, answered once and remembered across restarts. A push that ntfy does not answer is not retried: the status shows it as failing.
- 2026-11-03: Codex adversarial review of M3 (Ezra: fix three, defer one). Fixed: a phone that registers while an alert is open is sent that alert once (the watcher keeps the endpoints it has seen in its state); `hdroid-push` syncs run one at a time per machine and write again when the registration changed meanwhile, so the machine ends on the latest endpoint; a notification tap goes through a non-exported activity and the exported launcher takes no terminal from an intent. Deferred: a "Finished" that happens while the watcher is down, or during a restart's grace delay, is not alerted. The spec promises restarts lose no blocked agent, which holds; finishes are a quiet channel. Revisit if it is missed in use.
- 2026-11-03: V1 ships as built (Ezra): M0-M3, released once the M3.5 overnight check passes. Two features follow at once, each as its own OpenSpec change before any code: starting agents from the phone (reverses "not planned: starting new agents"; open: what may be started, in which folder, and how it shows in the desk's layout, since herdr-push keeps terminals outside a herdr-app pane quiet) and an optional always-on status notification that also keeps the connection open (open: the foreground service, battery, and reconnecting while locked, as the phone key signs only for 30 minutes after an unlock; possibly an Android 16 status-bar chip). Both are listed in the README as planned, without a version.
- 2026-11-03: Idea, later than v1.1 (Ezra): read an agent's answers aloud with Android's text-to-speech and reply by dictation (the compose sheet already takes dictation). Open: GrapheneOS ships no TTS voice (one must be installed), and only the agent's last answer should be read, not the screen's borders and tool output.
- 2026-11-04: Public repository, and main only changes through a pull request (Ezra). A repository ruleset on main requires a pull request (no approval: one maintainer), the `ci-ok` check, a linear history and rebase merges, and blocks force pushes and deletion, with no bypass. CI runs on pull requests and by hand, no longer on pushes to main (the same commits already ran in their pull request, and a release tag runs every test again). A pull request that touches only docs, specs, designs, research or Markdown skips the heavy jobs; `ci-ok` counts skipped jobs as passed, as a workflow-level path filter would leave the required check waiting forever. Merges rebase, so commits get new hashes on main; tags are made after the merge, so the release check is unaffected. Licence: Apache-2.0. The herdr.dev reference screenshots are no longer tracked.
- 2026-11-13: A chat view comes after all (Ezra), reversing "No chat-style composer" (2026-10-31): a second view of an agent, switchable with its live terminal, that shows the conversation as formatted text with tool calls folded, like the Claude and ChatGPT Codex mobile apps, and that also sends messages (a message box, as those apps have). The terminal stays the first view: herdr is terminal-first and the terminal had to come first; the chat view is the second view on the same agent, not a replacement. It starts with a spike: matching a terminal to its agent's session log. Reference screenshots are local (not tracked).
- 2026-11-13: v1.0.0 and work tracking (Ezra). v1.0.0 means the supervision loop is complete and someone else can set the app up and trust it without help: Stay connected, the chat view (reading and answering), mute and the Changes view (M5), plus setup tried from zero, a first-run check, a security review with `SECURITY.md`, accessibility basics and a supported herdr-core range. Work is tracked in GitHub issues with `v1.0.0` and `1.x` milestones and a public "herdr-android roadmap" board; issues link their OpenSpec change, which keeps the tasks.
- 2026-11-13: Stay connected wrap-up (Ezra). The battery cost ships as words, not a figure: the row says "Shows a notification, uses more battery" and the README says it depends on the phone and on how busy the agents are. The measurement (test phone, alternating 6-hour blocks on and off, a lower bound) runs after the archive and its result goes to the Stay connected issue; a large cost becomes its own change (Battery Saver, idle stops). Text contrast and Stay connected are switch rows, like Mute alerts, as plain rows did not look like options; "Text contrast" became "Higher text contrast" so the switch says what on means. GrapheneOS hides silent notifications on the lock screen when set to, so the counts show there only with "Show conversations, default and silent" (README).
- 2026-11-14: The Stay connected battery cost goes in the README as a measured figure after all (Ezra), as average current rather than a share of the battery a day, since battery sizes differ: about 22 mA more with the screen off (test phone, alternating 6-hour blocks: 92 and 93 mA on, 70 and 69 mA off), with the conditions that make it a lower bound (the phone was kept awake anyway; agents were not busy). The numbers are in the Stay connected issue. The SSH keepalive every 15 s is the likely main cost and the first lever if it needs lowering.
- 2026-11-14: Chat view settled (Ezra, proposal decisions 1-7). A message sent while the agent works goes in as the agent's own box takes it (Claude Code queues it, Codex takes it into the turn); its bubble reads "Queued" while the agent holds it. In scope: everything the spike showed, plus answers fading in as if typed, swiping between a message's images, and a context gauge (Codex: percent and tokens; Claude Code: tokens only, its log has no window size). After the agent exits or its log turns unreadable, the chat keeps what it read without the message box; opened afresh, the terminal shows. A message that does not reach the log reads "Not in the conversation yet" 30 s after sending (when queued: after the agent stops working), never while a command runs. No setting to turn the chat off; the switch hides when the log cannot be read. After a `/` command that may have opened a dialog, the box refuses until the command shows, the status changes or Dismiss is tapped. Codex images whose file is gone show "Image not available". Plan limits, verb themes, the terminal's rows while a command waits, session switching, `/` completion, the start hook and the Codex image fallback become 1.x issues.
- 2026-11-16: Chat view, changed during the phone checks (Ezra). A typed `/` command that writes no row reads "Sent to the terminal", not "Not in the conversation yet". When a turn ends, the working line stays until the answer is read (at most 3 s), so the chat never shows neither. A `/` command's wait ends once the screen shows the agent's input box free (Claude Code: nothing between its rules; Codex: its status footer), and the waiting line shows only after such a read. The fade stays at 600 ms, revealed from the top. Claude Code's thinking summaries (`thinkingDisplay: "updates"`) show as quiet rows; raw thinking stays hidden. While the chat shows, the terminal under it watches at the desk's size, so the desk keeps its layout; the terminal view takes the phone's size as before. Added to the 1.x list: renaming panes and agent titles, files the agent sends to the person, the agent list grouped by space, the 5-hour and weekly windows and the context percentage in the gauge's sheet, and taking a queued message back.
- 2026-11-16: Mute a session (#18) moves from v1.0.0 to 1.x (Ezra): a small idea, not needed to complete the loop. The chat view's later ideas became issues #37-#47 in 1.x.
- 2026-11-16: Changes view (#19, Ezra). A Changes button in the title bar of the terminal and the chat lists what is not committed yet in the agent's repository (staged, unstaged and untracked, from the repository's top), with lines added and removed, and shows each file's diff, wrapped with a continuation mark, never scrolling sideways. Read-only: git runs from fixed argument lists with optional locks, the file system monitor, external diff drivers and text conversion off; filters the repository configures (Git LFS) may run, as for any `git status`, but nothing takes a lock or writes under `.git`. The screen reads on opening and on each status or turn event while it shows, never with the phone's screen off, and sends nothing to the terminal. A diff shows its first 2,000 lines with "Show the whole diff (N lines)"; one past what herdr-core returns in one call (8 MB, the exception to decision 5) or past 50,000 lines reads "Too large to show on the phone" (the line cap came out of the Codex adversarial review: 8 MB of near-empty lines would be millions of records on the phone). The branch's commits not on main (#52) and the chat's tool sheet showing an edit as a diff (#53) are 1.x. Build choices: a new or added file shows no "−0"; "Too large to show on the phone" stays in view under the title bar; a diff that is only a note (binary, empty, a mode change, a submodule) shows it centred; opening Changes only hides the phone's keyboard, and the phone's grid is held until back, so the desk keeps its size under a permission prompt.
- 2026-11-18: Security review before 1.0 (#22, Ezra). Two independent reviews (Codex and Claude), each finding checked against the code. Fixed: the chat's second Enter goes as a guarded `terminal.send` of one space, so herdr-core refuses it when a dialog opened (an empty send leaves Claude Code's message in its box); the phone ignores a push no newer than the last from its machine and counts silence from when the desk sent it, and herdr-push pads every push to 1024 bytes; a picked photo is read up to 64 MiB; chat copies are marked sensitive; Recents keeps no picture of the app (Android 13+); compose text with a line break is refused where the program did not ask for bracketed paste; the spike's unpinned SSH call is only in the spike build. Accepted for 1.0: one push subscription for every machine, so one compromised machine could fake or clear another's alerts (#70, low: that machine is already lost); a chat send to a finished agent has no guard in herdr-core (#71). Looked sound: host key pinning, the Keystore key, the forced command, backups, exported components, push delivery, desk commands.
- 2026-11-19: The app is called Kudde (Ezra), Dutch for "herd": one group of agents working as a whole, and still a nod to where it came from. It is growing past a phone port of the herdr desk app, and the herdr name and the `dev.herdr` package belong to the herdr project. The package becomes `dev.kudde.android` (kudde.dev is the project's domain, which redirects to the repository until there is a site), the repository `enhulsman/kudde`, `herdr-push` becomes `kudde-push` (signature namespace `kudde-push`, same signing key, now in the secret `KUDDE_PUSH_SIGNING_KEY`). Kudde installs as a new app, so machines, the phone key and alerts are set up once more; a machine list exported from the old app still imports. What means herdr-core, the herdr desk app (`herdr-app`, `herdr.space`) or herdr's protocol (`herdr-proto`) keeps its name, and so does history (archived changes, research, release notes). The ram icon stays. Released as v1.0.0 under the new name.
