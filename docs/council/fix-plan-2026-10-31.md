# Fix plan: android-client-v1 after council 2026-10-31

All fixes are spec edits in `openspec/changes/android-client-v1/` (proposal.md,
design.md, tasks.md, specs/*). No code exists. Items follow the council's order.
Owner decisions are marked **[owner]** with the default the spec will carry until
Ezra answers; each is asked one at a time after this plan is approved.

## F1. Doc names (council 1, CRITICAL)
- Rename to `hdroid-push` and `hdroid-push-status` everywhere (design §5, alerts spec).
- New requirement in alerts: client doc names SHALL satisfy herdr-core's name rule
  (1-32 of `a-z 0-9 - _ .`, leading letter/digit, not id-shaped); test against a
  port of `check_name` and against the scratch core (`doc.set` succeeds).
- Q2 reworded: "is a client-claimed flat doc name acceptable as a stable contract?"

## F2. Alert delivery path (council 2 + watcher endpoint allowlist)
- `hdroid-push-status` gains `{last_post_at, last_post_status, last_ok_at, per-endpoint status}`;
  app requirement: show "Last alert delivered hh:mm" per machine, and "Alerts failing: <status>"
  on 403/404/410/5xx or when `last_ok_at` is older than the last attempt. Scenario for 403.
- "Send test alert" action: app writes a `test` request id into `hdroid-push`; watcher sends an
  encrypted test push through the real path; app shows received/not received within 30 s.
- ntfy auth: watcher uses a write-only ntfy **access token** scoped to `up*` (stored 0600 in the
  watcher config), anonymous access stays denied. This removes the per-topic grant, so
  re-registration needs no VPS change. Design §5 and impact updated; MollySocket's anonymous
  grant untouched. (If ntfy cannot scope a token to `up*` for write, fall back to an anonymous
  `up*` write grant, stated in the spec with its risk: anyone can post to any `up*` topic,
  bounded by unguessable topic names.)
- Registration while unreachable: scenario stating the honest limit: a new endpoint reaches a
  machine only when the phone next connects to it; the app shows "Alerts not registered on
  <machine> since endpoint change" until then.
- Endpoint allowlist: watcher SHALL POST only to endpoints whose scheme+host match its local
  config (default `https://ntfy.example.org`), https only, no redirects, 10 s timeout, body cap
  4 KiB; entries failing the check are ignored and reported in push-status. Test with a
  foreign-host endpoint.
- Watcher core discovery: SHALL connect only to an existing core (never autostart), session and
  socket from explicit config; SHALL report "no core" / "core has zero terminals" in its log and
  push-status rather than idling silently. Install notes give the systemd
  environment (`HC_SESSION`, `HC_SOCKET` or XDG paths).
- Early spike moved to M0 (see F9): encrypt, POST through ntfy, receive and decrypt on the
  phone; settles VAPID (Q5) and binary-body delivery.

## F3. Attention and alert rules (council 3)
- New section in agent-list spec: the state model ported from `model.rs` as a transition
  table: `error` counts as blocked; "done" = busy (working/blocked/error) to non-busy; records
  with `parent` and (for the watcher) terminals not placed in any pane are suppressed. The agent
  list orders blocked (incl. error, shown red) > done-unseen > working > idle.
- `herdr-proto::attention` is the single implementation, used by app and watcher; tests from
  the table plus a parent/child fixture.
- Watcher persists per terminal the last alerted `(state, turn)` in its state dir; on start it
  alerts for currently blocked terminals not yet alerted, never twice. `missed` + fresh
  snapshot: diff against persisted state, not against nothing.
- Grace delay before "Needs you": configurable in watcher config, default 30 s; cancelled if
  the terminal leaves blocked. "Finished" has no delay. **[owner]** default value.
- Watcher sends an encrypted `cleared` push when an alerted terminal leaves blocked; app removes
  the notification on it (works with the app closed). Scenario "answered at the desk, app closed".
- Maintainer question added: viewer presence or last-input time on the Terminal record.

## F4. RPC semantics, timeouts, flow control (council 4)
- Composer: working agent -> "Send when idle" implemented as client queue: `terminal.wait`
  (status) then `terminal.send {if: idle}`; on `status_mismatch` re-wait (max 3 tries) then
  show "Not sent: agent busy". Scenarios: status_mismatch, user cancels queued send, app
  backgrounded with a queued send (queue dropped, user told).
- Keys: row = esc, tab, ctrl (sticky), arrows, enter, ctrl+c; shelf = y, n, 1, 2, 3, /, -, .
  Requirement: every row/shelf key SHALL be accepted by `keys::encode` (test). `|`, `~` and other
  symbols go through direct typing only.
- Typing without Enter is only possible in direct typing (stated).
- Per-method timeouts: send 20 s, interrupt 15 s, keys 5 s, other calls 10 s; on timeout for
  send/keys/interrupt the UI shows "Outcome unknown, check the terminal", never "failed".
- Flow control: client SHALL send CREDIT as it consumes data on attach and event channels;
  test with >1 MiB of output.
- Dead link: no frame (incl. the core's 15 s heartbeat event) for 45 s -> reconnect; SSH
  keepalive 15 s.
- Frames larger than 16 MiB rejected before allocation; plain-to-framed switch after `hello`
  tested; output before the first JSON line (shell rc noise) skipped up to 64 KiB, then fail.

## F5. Size and reattach rules (council 5)
- Observe view: on a `size` event for the open terminal, discard the local VT, reattach at the
  new size. Any reattach starts with a fresh VT. Requirement wording "no stale content after
  reattach" replaces "no duplicate first paint". Test: size change mid-stream.
- Direct typing: attach with `resumed: true` until the first keystroke; follow `size` events;
  in "Keep their size" mode send RESIZE with the current core size before each burst after a
  size change. The phone sends display facts equal to the current theme's colours and its real
  cell size. Test: "Mac resizes during direct typing".
- Headless default 200x120 when no desk viewer: view opens fit-to-width and offers "Use phone
  size" (direct typing semantics).
- Version policy: protocol suite runs against pinned (0.1.15) and latest release in CI; the app
  warns when a core is newer than the newest tested and disables direct typing there.
- Runtime check: after an observe attach, `terminal.get` size compared with the size before;
  mismatch logged and shown as "desk size changed" (diagnostic).
- Proposal's claim that terminal-view covers 0.1.16 replaced by these requirements.

## F6. Signing, dependencies, phone key, sshd (council 6)
- Release spec: build job produces the unsigned APK from the tagged SHA; sign job has no
  checkout, downloads that artifact, verifies its SHA-256, runs pinned `apksigner` only.
  Environment deployment policy: only `v*` tags protected by a ruleset; workflow files
  protected by ruleset/CODEOWNERS. Approval checklist in the release notes: SHA and diff link
  since the previous release.
- `Cargo.lock` committed, Gradle dependency verification metadata, `cargo-deny` (advisories,
  licenses, sources) in CI before the approval job.
- `herdr-push` binaries published with SHA-256 sums, signed by the same gated job (minisign or
  GPG detached signature; install notes verify it).
- Per-machine scenario: with the phone key, any command other than the forced herdr-core command
  is refused (test against the real sshd on each machine at the M1 phone check).
- Forced command quoting: the exact `authorized_keys` line generated by code, tested by parsing
  with `ssh-keygen -l -f` and against a throwaway sshd in CI.
- Mac: Ezra confirmed 2026-10-31 that the phone cannot SSH into the Mac. v1 supports WSL only;
  the machine model stays multi-machine (more OpenSSH machines can be added later), but every
  scenario that names the Mac is rewritten with a generic second machine or dropped, and the
  Mac watcher and launchd unit leave v1. Parked idea (not v1): Mac alerts only, through a
  watcher with a static endpoint in its config (outbound to ntfy only), without opening its
  terminals; also ask maintainers whether a core that another core dialed into can list that
  core's terminals (the Mac already dials WSL).
- Keystore user authentication: **[owner]**. Default carried in the spec: key usable without
  authentication, plus a required app lock (biometric/device credential) on opening the app
  after 15 minutes in the background; background reconnects keep working.

## F7. Data shapes (council 7)
- Layout parsing per tab and node via `serde_json::Value`; unknown node types and mod panes
  shown as a placeholder tile; a malformed tab is skipped with a note. Scenarios: mod pane,
  unknown node type, malformed tab, unknown fields.
- Focus rule for opening a tab: first terminal pane in tree order, preferring blocked, then
  done-unseen. Test.

## F8. Testable acceptance criteria (council 8)
- Fidelity: cell-grid goldens (text + attributes per cell) from synthetic recorded byte streams,
  compared between libghostty on device/JVM and a golden dump. No Mac pixel comparison.
- Looks: Ezra signs off the rendered screens once; Roborazzi records goldens from the app; CI
  fails on diffs beyond tolerance. Appearance requirement reworded accordingly.
- Performance: p95 frame time <= 16.7 ms on the Pixel (Macrobenchmark), 200x60 continuous
  output; "instant open" = cached local VT state shown within 200 ms of tap (measured on
  device). Both device-only, run at phone checks, not CI.
- Instant-open cache: last VT state per terminal in app-private storage, encrypted at rest by a
  Keystore key, wiped when a machine is removed and after 7 days unused.
- Selection uses the local VT scrollback; `terminal.read` only with `lines: 0`.

## F9. Order and early spikes (council 9)
- M0 adds three spikes, each with a pass/fail rule:
  (a) device smoke test: load the `.so` on the Pixel, feed a recorded Claude Code stream, read
      the grid, draw one static 200x60 frame; fail -> switch to Termux fallback before M1;
  (b) russh + Keystore signing; fail -> Ed25519 wrapped key; the chosen key type is written into
      the spec before M1.4;
  (c) push end to end (F2).
- design.md: uniffi carries control and state; terminal frames go through a separate path:
  changed rows only, packed into one direct ByteBuffer per frame.
- Milestone order **[owner]**, default value-first: M1 list; M2 answer from a text view
  (local VT text from an observe attach, composer, keys row); M3 alerts; M4 live terminal view,
  zoom, direct typing; M5 spaces, wide layout, themes; M6 Changes.
- MVP cut **[owner]**, default: v1 = M1-M4; tiles, peek, rail, six themes beyond graphite/paper
  and Changes become v1.1.

## Round 2 revisions (after scoped scrutiny; these supersede the text above where they differ)

### R1. F2: "accepted" is not "delivered" (objection 1)
- The watcher field is `last_accepted_at` / `last_accept_status` ("accepted by ntfy"); nothing in
  the app calls an ntfy 2xx "delivered".
- Canary: the watcher sends an encrypted `canary` push every 6 hours through the same path as real
  alerts (same endpoint, same token, same encryption). The app silently records, per machine, the
  time of the last push of any kind it received.
- A periodic local check on the phone (WorkManager, every 6 hours, works with the app closed)
  posts a "Needs you"-channel notification "Alerts from <machine> silent since hh:mm" when no push
  from that machine arrived for 13 hours (two missed canaries plus margin). This detects dead
  topics, revoked notification permission, Doze or distributor problems without the phone being
  on the tailnet. Scenarios: dead topic (ntfy returns 200, nothing arrives) -> warning after 13 h;
  notification permission revoked -> warning shown in-app on next open.
- The ntfy bearer token SHALL be sent only to the allowlisted scheme+host; test that a foreign-host
  endpoint receives neither the POST nor the token.
- Android 13+ notification permission: requested at alert setup; if denied, the app shows alerts as
  off for every machine (scenario).

### R2. F5: attaching never moves the desk size (objection 2)
- Replaces "attach with `resumed: true` until the first keystroke". In "Keep their size" mode the
  phone reads the terminal's current `cols`/`rows` (`terminal.get`) and attaches with exactly that
  size, re-reading after any `size` event and before each typing burst.
- Display facts: the phone sends `display` with all fields null in "Keep their size" mode; whether
  null leaves the desk's facts in place is verified against viewers.rs `apply_size` during M4 and the
  requirement states the verified behaviour. If null fields clear the desk's facts, the spec states
  that theme queries may be answered with the phone's theme colours while the phone leads.
- Test: "desk viewer resumed and idle (active_at None), phone attaches in Keep their size: terminal
  size and display facts unchanged."

### R3. F6: the human approval is the control (objection 3)
- The release spec names the control explicitly: before approving the sign job, Ezra checks in the
  GitHub web UI (not in the run's own output) that (a) the tag's commit is on protected `main`, and
  (b) `.github/` has no changes since the previous release tag (compare view). The approval is
  done from the phone. The run-generated checklist is a convenience only and is not the control.
- Tag ruleset and workflow protection stay as defence in depth; the spec states they are bypassable
  with the owner's own credentials, which may sit on WSL.
- The sign job additionally fails if the tagged commit is not an ancestor of `origin/main`
  (cheap automatic check, also bypassable, so not the control).

### R4. Non-blocking items
- F3 suppression fallback: if the `herdr-app` doc is unreadable or a tab was skipped as malformed,
  the watcher treats terminals it cannot place as "in a pane" (alerts rather than silence) and
  reports "layout unreadable" in `hdroid-push-status`. Pane lookup normalises terminal addresses
  (`t7` and `<machine>/t7` both resolve to the local terminal when the prefix names this core;
  rule verified against the WSL doc during M3 and written into the spec).
- F3 "Finished": the same grace delay applies, cancelled when the terminal returns to working.
- F6 key default reason corrected: the app lock protects the open UI; the key itself stays usable
  without authentication because connections are made only while the app is open or within 60 s
  after it goes to the background, and alerts need no key at all.
- F9 MVP cut made consistent with the value-first order: v1 = M1 list, M2 answer from text view,
  M3 alerts, M4 live terminal (with themes graphite and paper only, following light/dark).
  v1.1 = M5 spaces drawer, tab overview, peek, wide-layout rail, the other four themes; M6 Changes.
  The effort estimate in proposal.md becomes "v1: 150-250 h (low-moderate confidence)".
- F8 fidelity goldens come from herdr-app's own VT pipeline (`vt.rs` over libghostty-vt at the same
  Ghostty pin `1e5cdb8`, run on the desktop over the same recorded byte streams), so they test
  fidelity to the desktop, not only regressions.
- F6 quoting: `ssh-keygen -l` only checks the key; the forced-command quoting is tested solely by
  the throwaway-sshd test in CI (stated).
- Doze and notification permission: covered by R1's canary and permission scenarios.

## Round 3 notes (scrutinizer round 2 objection, applied; not re-reviewed)
- R1 correction: the silence warning goes to a third, quiet channel "Alert health", posted once per
  silence period, text "No word from <machine> since hh:mm: the machine is off or alerts are
  broken.", cleared by the next push from that machine. Scenario: machine off for 20 h -> one quiet
  notice, no "Needs you" alert.
- R2 closed: `set_display` skips null fields (`herdr-core/crates/ghostty-vt/src/lib.rs:561-574`), so a
  null `display` leaves the desk's colours in place; the requirement states this, fallback wording
  dropped. Cell-size branch to confirm in the M4 test.
- R3: the ancestor-of-`main` check runs in the build job (full-history checkout) or via the GitHub
  API, not in the sign job.

## Owner decisions applied (2026-10-31)
- Order replaces F9's value-first default: M1 list; M2 live terminal + keyboard; M3 alerts; M4
  spaces/wide/themes; M5 Changes. M0 spikes unchanged.
- Input: no `terminal.send` composer. Typing, the keys row and the compose key go through the
  non-observe attach stream, encoded by libghostty's key encoder (so `|`, `~` and any key work;
  F4's composer flow, `if: idle` queue and shelf restriction are dropped; F4 timeouts, CREDIT,
  dead-link and frame limits stay). Compose key: a text field whose text is sent as a bracketed
  paste, no Enter. Long-press esc keeps `terminal.interrupt`.
- Size: watching = observe attach. First input = attach as an active viewer at the phone's size, no
  dialog; the desk retakes its size on its own next input (herdr's normal last-active rule).
  R2's "Keep their size" mode is dropped from v1; its null-display finding still applies (the
  phone sends a null `display` unless verified otherwise). Test: phone types, terminal takes phone
  size; desk types, desk size returns; watching never changes size.
