# M1.5 phone check

The checklist for the end of M1 (tasks M1.5, and M0.8 which closes with it):
the phone connects to your workstation (WSL over OpenSSH) with its hardware
key and lists every agent, the ones that need you first. Work through it with
v0.0.2 installed and set up first, then v0.0.3 installed over it.

Try each step first against a spare test machine (any Linux machine with
OpenSSH that nothing else depends on), especially the steps that switch a
machine off or change its `authorized_keys`. Never use a machine other
services rely on for those.

Write each result on its `Result:` line here, in plain words and without real
host names, addresses, ports or project names (this file is tracked). The two
decisions also go into `decisions.md`; tick M1.5 and M0.8 in
`openspec/changes/android-client-v1/tasks.md` when their items pass. Anything
that fails becomes a follow-up before M2.

## 2. Add your workstation

- [ ] Machines > Add machine: name, host, port, user. The form refuses a name
  that is already used.
- [ ] Phone key screen: copy the line and add it to `~/.ssh/authorized_keys` on
  the workstation, on one line, unchanged.
- [ ] The app shows the workstation's host-key fingerprint. Compare it with the
  workstation's own, before tapping Trust and connect:
  `ssh-keygen -lf /etc/ssh/ssh_host_ed25519_key.pub` (or the key type the app
  names).
- [ ] The machine connects. A screen unlock counts as the key's
  authentication for 30 minutes, so the "Unlock the SSH key" prompt only
  shows when the phone was last unlocked longer ago than that; no second
  prompt within those 30 minutes.

Result: line added, fingerprint matched the test machine's, connected without
a prompt (the phone had been unlocked recently). FAIL, fixed for v0.0.3:
while the phone key was not accepted yet, every retry blanked the card's
detail and "Add phone key" row for a moment. Duplicate-name refusal: not
tried yet.

## 3. The key can only start herdr-core

On the workstation, from a checkout of this repository:

```
scripts/check-restricted-key.sh --live
```

It reads `~/.ssh/authorized_keys` (never changes it), checks the phone's line
(`restrict` set, nothing re-enabled, `command=` is the app's herdr-core command,
no unrestricted copy of the key in any file sshd reads keys from, only you
can write the file), then starts a
throwaway sshd on 127.0.0.1 with a temporary key and the same options and asks
it for a terminal, another command, a local and a remote port forward. Every
line must say PASS; it exits non-zero on any FAIL. For sshd's own settings as
well (needs root to read them):

```
sudo sshd -T -C user=$USER,host=localhost,addr=127.0.0.1 > /tmp/sshd-settings
scripts/check-restricted-key.sh --live --sshd-settings /tmp/sshd-settings
```

- [ ] All PASS, including the sshd settings.

## 7. Pocketed: no session left open after 60 seconds

On the workstation, count the herdr-core sessions. Other clients (the desk
app) have their own, so compare against a baseline:

```
pgrep -fc 'herdr-core connect'
```

- [ ] App closed: note the baseline. App open on Agents home: one more.
- [ ] Lock the phone and pocket it. After 60 seconds, plus some slack, the count
  is back to the baseline. Note how long it actually took.
- [ ] Unlock and open the app: it reconnects (within the key's 30 minutes,
  without a new prompt).

Android may hold the app back while the screen is off (GrapheneOS's app
freezer, deep sleep): the timer uses an inexact wake-up alarm, so the session
can close late. Try it once on the charger and once off it, and note both
delays. You decide what delay is acceptable; well over a few minutes is a
follow-up.
