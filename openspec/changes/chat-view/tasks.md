Done 2026-11-16, Pixel 7 Pro on Wi-Fi, Stay connected on, with a fixture agent (a process named `claude` reporting "working", its session file, and a log gaining a Bash call every 25 s). The phone locks after 5 minutes whatever its setting (a work-profile policy), so the hour ran mostly with the screen off, and the screen-on figures come from 4- and 5-minute runs. Desk: with the chat of a working agent on screen, herdr-core used 2.2 to 2.6 CPU-seconds a minute more than with the agents list shown (two thirds in the read scripts it starts), about 4% of one core; with the screen off, nothing (the reads stop). A Missed agent in terminal view costs no more than the agents list. Found and fixed: with the screen off, the open chat of a working agent kept the app's main thread at about 18% of a core (the 250 ms clock and the working line's loops ran on): 12 CPU-minutes in the hour, 12.3 mAh estimated against Stay connected's 6.1 to 6.7 mAh an hour. After the fix, 2.6 CPU-seconds and 3.3 mAh in 30 minutes, Stay connected's own cost. Seen, not changed: any screen that keeps animating costs about 30 to 40% of one core in the app, as each frame redraws the whole screen (non-debuggable build, 60 Hz: drawing thread 17%, main thread 14%); that holds for the chat's working line and for the agents list's spinners from V1, against 1.5% for the terminal view. Memory: about 200 to 230 MB with the chat on screen (Java heap 15 to 37 MB), 107 to 120 MB in the background, no growth over the run. Growth over an hour on screen was not measurable (the lock); with the screen off nothing is read, and an open chat holds only what it read since it opened (the recent part, older parts on scrolling up, live rows), so no cap was added
